# Benefits Ops Desk

A small demo of how a Benefits Specialist can cut manual work: three checks and a routing workflow, built on **fully synthetic data**. No real employee, vendor, insurer or company data is used anywhere in this repo.

Built with Python, Streamlit and n8n, with Claude used as a coding assistant during development.

## What it does

| Module | Problem it addresses | Where |
|---|---|---|
| **Invoice check** | Compares a vendor invoice with contract rates and headcount. Flags rate differences, duplicate lines, leavers still billed, billed members missing from the employee file, and active members missing from the invoice. | `checks.invoice_check`, app tab 1 |
| **Eligibility and leaver checks** | Scans the employee file for enrolment before the waiting period ended, part-time or contractor staff on full-time-only plans, leavers without a leaver date and duplicate records. Exports a corrected file with a review flag. | `checks.eligibility_check`, app tab 2 |
| **Request router and reminders** | Classifies incoming benefits questions by topic, assigns an owner and SLA, and drafts renewal and enrolment-deadline reminders. | `checks.route_requests`, app tab 3, `n8n/` |

The synthetic data has errors planted on purpose (seeded, so the results are reproducible): 2 overbilled rates, 1 duplicate invoice line, 1 unknown member, 1 missing member, early enrolments, ineligible plans, a leaver without a date and a duplicate employee record.

## n8n workflows

The `n8n/` folder has three importable workflows:

- `request_router.json`: a webhook receives a JSON body `{"requests": [{request_id, employee_id, message}]}`, splits it and classifies each message with the same rules as the Python version.
- `renewal_reminders.json`: runs every Monday at 08:00 and drafts reminders for provider renewals due within 90 days.
- `error_alert.json`: an Error Trigger workflow that formats an alert when another workflow fails. Set it as the error workflow in each workflow's settings.

Import: in n8n choose **Workflows > Import from file**. The JSON is generated by `n8n/build_workflows.py` from the routing rules in `checks.py`, so the app and the workflows stay consistent.

Test the router after activating it:

```bash
curl -X POST <your-n8n-webhook-url>/webhook/benefits-request \
  -H "Content-Type: application/json" \
  -d '{"requests":[{"request_id":"R1","employee_id":"E1001","message":"My last day is 31 October"}]}'
```

Expected category: `Leaver`.

## Run it

```bash
pip install -r requirements.txt
python generate_data.py        # regenerate the synthetic data
python -m pytest -q            # 5 tests
streamlit run app.py
```

## Limits (stated honestly)

- Rules (90-day waiting period, full-time-only plans, rates) are invented for the demo. Real schemes differ by country, insurer and contract.
- The router is keyword-based. It is a first filter for a human, not a replacement for judgement on complex cases.
- Nothing connects to a real HRIS, payroll system or insurer.
- Estonian, Polish, Portuguese and German statutory rules are not modelled.
